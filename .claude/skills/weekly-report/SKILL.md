# 週次レポート作成スキル

このスキルは oncall-appnpx プロジェクトにおける直近1週間(または指定期間)の開発作業を
まとめた日本語の週次レポートを作成する。

## 手順

### 1. 対象期間を決める

- 引数や会話で期間の指定があればそれに従う(例: 「先週分」「9/1〜9/3」)。
- 指定がなければ「直近7日間」をデフォルトとする。開始日は `today - 7 days`、終了日は今日。

### 2. 変更内容を収集する

まず `git rev-parse --is-inside-work-tree` などでこのディレクトリがgit管理下か確認する。

**gitリポジトリの場合:**

```
git log --since="<開始日>" --until="<終了日>" --date=short --pretty=format:"%ad %h %s"
git diff --stat "@{<開始日>}"..HEAD
```

コミットメッセージと変更ファイルの統計から、変更点を分類・要約する。

**gitリポジトリでない場合(現状このプロジェクトはgit未初期化):**

git履歴が使えないため、ファイルの更新日時をフォールバックとして使う。
`node_modules`、`.next`、`.git` 等を除外し、対象期間内に更新されたファイルを列挙する
(PowerShellなら `Get-ChildItem -Recurse | Where-Object { $_.LastWriteTime -ge <開始日> }`、
Bashなら `find . -newermt "<開始日>" -not -path "*/node_modules/*" -not -path "*/.next/*"`)。

各ファイルについて、可能であれば実際の差分内容(直前の会話履歴やファイルの中身)から
何が変更されたのかを把握し、単なるファイル名の羅列で終わらせない。
どうしても変更内容が分からないファイルは「更新内容不明」として一覧に含めるに留める。

レポートの最後に「※このプロジェクトはまだgit管理されていないため、正確な変更履歴を
追跡できません。`git init` して以降はコミット単位で正確なレポートが作成できます」と
一言添える。

### 3. 変更点を分類する

このプロジェクトの構造(CLAUDE.mdを参照)を踏まえ、変更を意味のあるカテゴリに分ける。例:

- 機能追加(例: 患者管理・当直引き継ぎ・物品管理まわりの新機能)
- 不具合修正
- UI/表示の調整
- リファクタリング・整理
- ドキュメント整備(README, CLAUDE.md, docs/ など)
- 設定・依存関係(package.json, next.config.ts など)

`app/page.tsx` のような単一の大きなファイルへの変更は、可能な範囲で
`currentView`(map/doctor/summary/supply/history)のどのセクションに関わる変更かも添える。

### 4. レポートを出力する

以下の構成で日本語Markdownとして作成する:

```markdown
# 週次レポート (<開始日> 〜 <終了日>)

## サマリー
(2〜4行程度で全体の要約)

## 主な変更点
### <カテゴリ名>
- <変更内容の説明>([ファイル名](パス) への言及があれば併記)

## 今後の予定・懸念事項
(分かる範囲で。特になければ「特になし」)

## 備考
(gitフォールバック使用時の注意書きなど)
```

作成後は次を確認する:

1. まずレポート全文をチャットに提示する。
2. ユーザーがファイルとして保存したいか尋ねる。保存する場合は
   `docs/weekly-reports/<終了日 YYYY-MM-DD>.md` に保存する(ディレクトリがなければ作成)。
   ファイル名の日付は必ず終了日(通常は今日)を使う。
3. 既存の `docs/weekly-reports/` にあるファイルは上書きせず、同名があれば連番などで区別する。
